Rules:
- Output ONLY a JSON array, no prose, no Markdown fence:
  [{"op": "<operator>", "args": ["<node id>", ...]}, ...]
- At most <MAX> queries. Choose the fewest that answer the question; prefer one.
- Node arguments must be ids copied EXACTLY from the list above. If the question names
  a service that is not in the list, do not guess a similar id — omit that query.
  (The one exception is add-edge / add-node below.)
- "edges-of-type" takes one of: sync-http, db, async, external.
- Questions like "what happens if X goes down / who is affected by X" → impact-of.
  "What must be up before X / what does X need" → startup-needs.
  "Does X call Y / how does X reach Y" → path.
  "Which services use a database / who talks to the db" → db-users.
  "What was not covered / not exercised / not observed by traffic" → uncovered (and
  unobserved-edges if the user asks about all edges, not only business ones).
  "Deployment order / start-up order / what to deploy first" → deploy-order.
  "What is not deployed / missing from the cluster" → undeployed.
  "External dependencies / third-party APIs" → externals. "Queues / events / broker" → async.
- A business flow, feature or use case ("the checkout flow", "訂票流程", "login"), or a
  request to draw / show only part of the graph → subgraph, with the service ids that
  take part in it. Prefer services the excerpts say the flow goes through; otherwise
  choose by what the ids clearly denote (orders, payment, cart for checkout). Name only
  the services of the flow itself, not every database or gateway — code adds the paths
  between them and their neighbours. If no id plausibly belongs to it, output [].
- A follow-up that edits the previous partial graph ("add contacts too", "把 X 也加進去",
  "remove Y", "拿掉 Y", "only keep …") → subgraph with EXACTLY the previous subgraph's
  seeds, plus the nodes it names to add, minus the nodes it names to remove. Do not add
  or drop anything else. A new, unrelated request replaces the previous seeds.
- A request to CHANGE the graph — add an edge / line / dependency that is missing
  ("新增一條 X 到 Y 的線", "圖上少了 X → Y", "X 其實有呼叫 Y，補上去", "add an edge from X to Y")
  → add-edge with [caller, callee]; add a node / service ("新增節點 Z", "add Z to the
  graph") → add-node with [Z]. Output only that one query. These two may name services
  that are NOT in the list: copy the user's spelling exactly, do not map it to an id.
  "Y 被 X 呼叫" is still [X, Y]. A request naming only the callee ("加一條連到 Y 的線")
  → add-edge with ["", Y]. A QUESTION about an edge ("does X call Y?") is path, not add-edge.
- A request to REMOVE an edge / line / dependency that is on the graph and wrong
  ("把 X 到 Y 的線拿掉", "X → Y 那條線是錯的，刪掉", "X 其實沒有呼叫 Y", "remove the edge from
  X to Y", "X does not call Y, delete that edge") → remove-edge with [caller, callee],
  the user's spelling. Output only that one query. This is about the GRAPH; "remove Y" /
  "拿掉 Y" naming only nodes right after a partial graph is the subgraph edit above.
- If the question is about the report's text, limitations, collection status, or
  anything not answerable from the graph structure, output [].
- The question may be in any language; the operators and ids stay as written.
