[碩論] 「只畫對的、不畫錯的」要先讓④追得到：補三個綁定轉接器 3

想做的事：程式碼讀得到的容器，env 區塊裡的服務位址交給程式碼層畫（yas 的 storefront 被交到 10 個位址、一個都沒用）

第一次開：yas 錯邊消失，但掉 27 條真邊（yas 16、TeaStore 5、otel 4…）——程式碼真的有用，只是④追不到。逐條看是三種寫法：

Spring 三段式綁定

YAS_SERVICES_PRODUCT=http://product
↕ 寬鬆綁定
yas.services.product
↕ @ConfigurationProperties(prefix="yas.services")
record ServiceUrlConfig(String product)
↕ 存取子在呼叫點
fromUriString(serviceUrlConfig.product())

環境變數 ↔ 屬性鍵 ↔ 欄位 ↔ 呼叫點。存取子要在呼叫點那幾行才算，所以 cart → product（有用）畫、storefront（綁了沒用）不畫

映像的命令列

ENTRYPOINT locust \
  --host="http://${FRONTEND_ADDR}"

Dockerfile 的 ENTRYPOINT／CMD 和同目錄 *.sh 裡的 URL 是程式碼層的列，佔位符用該容器的 env 填。Online Boutique／Bank of Anthos 的 loadgenerator → frontend 由此畫出

FROM 鏈

dockerbase/start.sh:
  http://${REGISTRY_HOST}:${REGISTRY_PORT}/…
teastore-webui/Dockerfile:
  FROM descartesresearch/teastore-base

基底映像目錄的啟動腳本跑在每個建在它上面的映像裡：TeaStore 五個服務各自用自己的 REGISTRY_HOST 解成 → teastore-registry；沒有 manifest 跑的 all-in-one 不繼承

三個都是「值從哪來」的新路徑，不是新規則；做完再開那條延伸：hold-out C 0.87／0.97 → 0.98／0.98（yas 錯 13 → 2），其他組不變。

講稿　問題是 yas 的 storefront 被塞了十個服務位址，程式碼一個都沒用，描述檔卻照畫。要改成「程式碼讀得到就交給程式碼決定」，第一次開掉了 27 條真邊——程式碼確實有用，但工具追不到。追不到的三種寫法：Spring 把環境變數綁到一個 record 再經 getter 進呼叫；locust 的位址寫在 Dockerfile 的命令列；TeaStore 的位址寫在基底映像的啟動腳本。補了這三個轉接器再開，C 組從 0.87 到 0.98，別組沒掉。

字詞表：29 份、306 個詞，每份寫清楚三件事

清單（例）原則來源生態系
DB_SCHEMES（17）URI scheme 說目標是資料庫JDBC、MongoDB、Redis… 官方連線 URL
HOST_WORDS（8）鍵名最後一個字說值是主機Spring .host、.NET HostName、Nacos server-addr
INBOUND_WORDS（18）「誰能連我」不是我的相依CORS origins、OAuth redirect、AllowedHosts
CLIENT_CALL_*（45）這些呼叫會發出連線RestTemplate、HttpClient、requests、grpc…
SOURCE_STOP（35）這些目錄名不是服務Maven／Go／Node 的專案結構

新增一個詞的條件一律是「某生態系的文件這樣拼」，不是「某個受測系統需要」。清單由程式碼產生 vocabulary.md，測試保證一致。

靠資料決定的子句（審查會指著說「特例」的）

  • depends_on：自家容器且哪裡都沒位址 → 畫 inferred（純慣例會掉 hotelReservation 22 條）
  • links 與 depends_on 不同待遇（Compose v1 文件）
  • 程式碼產生工具有 main 就算服務（mall-mbg 那條錯邊就是它）
  • FROM 鏈只給有部署的子映像（TeaStore all-in-one）
  • 「同一層先」：server.port 贏過 Compose 發佈的 port（Tap-And-Eat）

每一條寫成「這一類寫法怎麼看」，程式碼裡沒有任何系統的名字；但「為什麼存在」的答案都是某個系統。論文打算把這幾條和字詞表列成一張表，比說「沒有特例」站得住。

講稿　判斷邏輯是四個慣例沒錯，但底下有兩層東西要老實列出來：29 份字詞表，像「哪些 scheme 是資料庫」「鍵名最後一個字是 host」，這些是各生態系的拼法，不是從慣例推出來的；還有五條靠資料定的子句，每條都是先遇到某個系統才寫的。我的想法是論文直接列表，不說「沒有特例」。
