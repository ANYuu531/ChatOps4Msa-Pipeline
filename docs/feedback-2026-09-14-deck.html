[碩論] AsianPLoP Pattern 1

Pattern 與 pattern language 是什麼

Pattern在某個情境下，一個反覆出現的問題的解法；要平衡互相拉扯的 forces（只有一個顯而易見的做法是常識，不是 pattern）
反覆出現不是單一系統的特殊做法；要有跨實例的通用性證據（慣例約三個 known uses）
Pattern language一組 pattern 串起來解一個更大的問題；套用一個，會產生下一個要解的情境（生成性）
一篇論文同一個問題、同一群讀者、同一個抽象層級，約 3–6 個

AsianPLoP 實際規定（2026 徵稿頁）：

  • Regular ≤ 20 頁、Short ≤ 10 頁；ACM 單欄模板；英文
  • 流程：初審 → shepherd 陪改 → writers' workshop
  • 沒有規定固定欄位或 known uses 數量，看 Hillside Pattern Writing Checklist
  • 2027 屆未公告；往年截止約 12 月至隔年 1 月

這篇怎麼符合這些要求

要求這篇的做法
同一個問題只回答：多來源合成的依賴圖與報告，讀者怎麼信任
同一個層級5 個都是「建構依賴視圖」時的設計決策
生成性每個 pattern 都寫 Resulting Context，接到下一個
反覆出現每個都有 DepWeaver 的真實事件，外加 ≥ 2 個查證過的外部實例
寫法Context／Problem／Forces／Solution／Consequences／Resulting Context／Known Uses
讀者用中性的線上商店當 running example，不懂微服務也看得懂
投稿形式：5 個 pattern ＋ running example 預估超過 10 頁 → 投 Regular paper（≤ 20 頁）
講稿　先對齊定義：PLoP 要的是 pattern language，同一個問題、同一層級，而且前一個 pattern 解完會產生下一個 pattern 的情境。右邊是這篇怎麼對應這些要求；AsianPLoP 徵稿頁本身沒有規定欄位格式和 known uses 數量，慣例看 Hillside 的 checklist。

[碩論] AsianPLoP Pattern 2

一個問題、5 個 pattern

問題：由多種可靠度不同的證據（遙測、程式碼、文件、LLM 整理）合成依賴圖與報告時，怎麼讓讀者可以信任每一條關係、每一個數字、每一句說法？

讀者：做「多來源合成視圖」工具的人（架構還原、資料血緣、服務目錄、SBOM、可觀測性儀表板），不限微服務。　根原則（放引言）：確定性優先，LLM 只補語言。

#Pattern解決的問題套用後產生的新問題 → 下一個
①證據分級的關係
Evidence-Graded Relations		所有關係畫成一樣，讀者分不出哪條是真的同一條關係被多個來源、以不同等級提到，要合在哪裡？
②單一標準模型
One Model, Many Views		圖、數字、報告各自推導，互相矛盾模型一致了，但 LLM 寫報告時重述事實仍會漂移
③事實由程式寫
Code-Authored Facts		LLM 重述事實會漂移，改 prompt 只是換一種錯數字由程式算了，但分母要算進哪些項目？
④誠實分母
Honest Denominator		分母混進量不到、證據弱的項目，分數失真有些項目、甚至整個指標根本沒量測，要顯示什麼？
⑤未量測不是零
Unmeasured Is Not Zero		沒量測被當成 0／false，或被 LLM 猜掉（終點）每個數字與說法都有依據，或明說沒有

同一條原則下的其他做法（補證迴圈、報告問答）留作後續論文

講稿　右欄是這版最重要的一欄：每個 pattern 解完，會自然產生下一個問題，這就是 pattern language 要的生成關係。例如模型一致之後，剩下的矛盾來源是 LLM 寫的報告文字，所以接 ③。

[碩論] AsianPLoP Pattern 3

展開一個：④ 誠實分母（Honest Denominator）

Context你用程式從模型算覆蓋率這類比率（接 ③）；模型裡混著量測不到、證據很弱（① 的「只被提到」）、性質不同的項目
Problem量不到的算進分母 → 永遠到不了 100%；弱證據算進去 → 文件多說幾句就稀釋；排除太多又虛高
Forces全算看似保守卻讓人去修修不好的缺口 ／ 排除會虛高 ／ 排除規則需要領域知識 ／ 分母一改歷史不可比
Solution分母只算量測得到且證據足夠的；不同量測分開算；一定揭露「未計分 N 項＋理由」；排除多於計分時警告
Resulting Context分母誠實了，但整個指標可能根本沒量測 → ⑤
Running example商店系統：分母 4 條業務呼叫；orders → shipping 只被提到，不計分但揭露；資料層另算 1/1

Known uses（已查證）：

  • DepWeaver：假 45% → 4/4；文件幻覺讓 7/7 → 7/10；程序內快取卡 5/6
  • CONSORT 2010／2025：流程圖每階段寫排除人數與理由
  • coverage.py：排除的行不進分母，但報告仍標出

反例（寫進 Forces 對照）：

  • JaCoCo：被過濾的程式碼直接從報告消失
  • Istanbul：略過的程式碼被算成「已覆蓋」
講稿　每個 pattern 都用同一組欄位，多了一欄 Resulting Context 接下一個。Known uses 這次上網查證過，每項都有官方文件或論文出處；JaCoCo 和 Istanbul 查完發現剛好是反例，拿來對照更有說服力。

[碩論] 門檻設計與實驗 2

判定式與代價

有把握 ＝ 第一名 ≥ H　或　( 第一名 ≥ T　且　第一名 − 第二名 ≥ M )
條件防的錯
T 最低分數圖上沒有對應意圖的問題被硬選
M 領先幅度兩個意圖打平（0.652 對 0.651）時硬選一個
H 高分捷徑已是例句原句等級，不必再看第二名

例（新門檻 0.51／0.10／0.80）：「前端依賴誰」第一名 1.00 ≥ H → 有把握；「ledgerwriter 何時呼叫 balancereader」0.75 對 0.66，領先 0.09 ＜ M → 交給 LLM planner

兩個方向的錯，代價不對稱：

  • 太嚴 → 多一次 LLM planner 小呼叫，只是變慢
  • 太鬆 → 有把握地選錯查詢 → 漏答

選定規則（跑之前寫進程式）：

「有把握但錯 ＝ 0」的前提下 coverage 最大；平手取保守（T 高、M 大、H 高）
